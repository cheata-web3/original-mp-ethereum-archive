# MPの作成者証明と確認手順

この資料は、MPを作成したアドレスと発信者を結び付けるための手順です。現時点では作成者ウォレットの署名が未提出であり、作成者証明の取得完了を意味しません。

## 何が分かり、何が未確認か

- **作成トランザクション**: Ethereum上のMPは、アドレス `0x102eEe422113140FBDc2544F495a947399AB100B` から2018年6月3日22:59:16 UTCに作成されています（[Etherscanの作成取引](https://etherscan.io/tx/0x6ffb1d00e827ae77b1e1940ac52d0abb3acbc6445ae19c6e981ac1a4aebedfeb)）。
- **現在の署名能力**: 未確認です。EIP-191の署名からアドレスを復元し、そのアドレスが作成者と一致するかを調べます（[ethersの署名仕様](https://docs.ethers.org/v6/cookbook/signing/)）。
- **本人との結び付き**: 署名にはGitHubアカウントとリポジトリを明記します。ただし、その記載自体は署名者の申告であり、本名・法人名の確認を代替しません。
- **過去の作成行為・著作権**: 現在の署名だけでは、当時も同じ人が管理していたことや、汎用コントラクトのソースを自作したことまでは証明しません。当時の記録や第三者の確認を別途組み合わせます。

## 安全な進め方

作成者アドレスを表示できるウォレットが今も手元にあるか確認します。秘密鍵・シードフレーズ・パスワードはGitHub、チャット、作業者へ渡さないでください。

1. リポジトリの検証を先に実行します。

   ```bash
   npm ci --ignore-scripts
   node scripts/verify-archive.js
   (cd archive && sha256sum -c hashes.txt)
   npm test
   ```

2. 未署名の文面を作成します。既存ファイルは上書きしません。

   ```bash
   node scripts/creator-proof.js prepare provenance/draft-creator-proof.json
   ```

3. 自分のウォレットで、JSONの `message` の値そのものを、通常のメッセージ署名として署名します。JSON全体ではなく、改行を含む本文だけが対象です。余分な末尾改行を加えないでください。署名画面で作成者アドレスと全文を確認し、取引送信、トークン承認、Permit、委任、ログインの要求なら中止します。
4. 得られた公開署名をJSONの `signature` に保存し、検証します。秘密鍵の入力は不要です。

   ```bash
   node scripts/creator-proof.js verify provenance/draft-creator-proof.json
   ```

5. 検証成功後、署名・アドレス・GitHubとの関連付けを公開してよいか確認します。承認後にのみ `provenance/creator-proof.json` として保存し、レビューを経て公開します。READMEとPROVENANCEの「未確認」表示も、その時点で実際の検証結果に合わせて更新します。

このツールは検証のみを行い、ウォレット接続・秘密鍵取得・送金は行いません。EIP-191メッセージ署名の生成と復元は、プロバイダーに接続せず実施できます（[ethersの署名例](https://docs.ethers.org/v6/cookbook/signing/)）。

## 検証結果の読み方

CIが成功しても、署名ファイルがなければ作成者証明は未完了です。テスト用のランダムなウォレットによる署名は、実際のMP作成者による署名ではありません。

署名文中の日時は自己申告です。GitHubの公開日時や別途取得する第三者タイムスタンプとは区別し、2018年当時に署名したかのような表現をしてはいけません。

## 作成者ウォレットが使えない場合

別のウォレットで署名しても、この作成者アドレスの管理証明にはなりません。当時の開発記録、作成依頼・納品記録、公開告知、端末内の原本などを整理し、証拠の種類と限界を明記します。

取引所提出、権利紛争、実名の証明などが目的なら、まず提出先の要求を確認してください。ここで生成する資料は技術的な検証資料であり、公的な認定証や法的判断ではありません。
